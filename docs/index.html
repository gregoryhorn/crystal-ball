01 / Perception

Four ways to look closer.

Local analysis by default. A vision provider only when you configure one.

01 — HEAR

Know what was said.

Word-timed transcription, script differences and labelled mix estimates. Beat detection adds tempo, onsets and estimated bars, downbeats and sections.

02 — SEE

Find the right shot.

Scene detection finds shots, fades and cached thumbnails. CLIP searches 1–3 frames per shot by phrase or reference image. Export shot lists and edit markers.

03 — READ

Catch visible details.

Full-size OCR, spelling hints and persistent safe-zone evidence. Lone characters stay uncertain.

04 — JUDGE

Ask for evidence.

One bounded visual critique. Your brief and rules, concrete findings, validated JSON and OCR cross-checks.

02 / The loop

From render to evidence.

Reuse the work. Frames, transcripts and embeddings live in a shared artifact cache.

Render

Make your video with the tools you already use. Hermes hooks can notice new and modified outputs.

Check

Measure signals, beats and cut pacing; read text and review cut frames. Flash safety estimates flag rapid luminance or red flashing: estimate, not a certified Harding test.

Compact verdict

Get small JSON with the important findings and a path to the full Markdown or HTML report.

Fix & re-check

Mechanical level fixes write a new .cbfix file. The original remains, and the output is checked again.

03 / Clear evidence

Small verdict.
Full paper trail.

Keep long transcripts, images and repeated findings out of the model's context. Follow artifact paths when you need the detail.

The standalone CLI and Hermes tool share the same engine. Tool results normally fit in 1,500 UTF-8 bytes and never embed images.

Check passed ≠ approved.
Static samples cannot hear, establish continuous motion or judge lip-sync. Two critique rounds, then human direction.

04 / Start local

A toolkit you can own.

Python 3.11+, ffmpeg and Tesseract. User-installed models. No bundled footage or weights.

Standalone

05 / No guessing

Know what is available.

crystal-ball doctor checks binaries, engine versions, local model checksums, CPU/GPU availability and configured fallbacks.

It never downloads. Availability diagnostics are separate from a successful live inference test. Missing components stay visible as WARN or FAIL.

Illustrative table; run doctor for your actual machine. Run opt-in live tests with CRYSTAL_BALL_LIVE=1.
